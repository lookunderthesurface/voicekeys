# GUI 重写需求清单（从对话里逐条收集）

> 用途：重写 `app/ui.html` 时对照，避免遗漏。备份在 `app/backup/ui-20261115-0040.html`。

## 布局与信息

1. **顶部状态条**：监听/录音状态灯、音频源、麦克风诊断（帧数、瞬时电平、2 秒峰值）、Handy 状态（录音中/空闲）。
2. **左侧主区**：计划与关键词编辑器（见下）。
3. **右侧**：校准面板 + Handy 控制面板。
4. **底部**：事件日志（听到 / 触发 / 丢弃 / 忽略 / Handy / 结果 / 错误）。
5. 刷新节奏 **1000ms**。

## 命令词 / 计划（核心）

6. **一个计划一行**：同一个计划的多个关键词合并显示在同一行（不是每个词一行）。
7. **每行都必须有「新增关键词」入口**：即使这一行已经有词，也要能再加同义词。
8. **列表末尾必须有「＋ 新增一行（新计划）」**。
9. **新增出来的空行里也要有初始的 ＋**（保持一致的交互逻辑）。
10. 点关键词名 → 选中为**校准目标**。
11. 点关键词上的 × → 解绑该词。
12. 关键词旁**直接显示/编辑阈值**（不再单独一张阈值表）。
13. 阈值输入不能被 1s 刷新覆盖（编辑中保留草稿，失焦/回车才保存）。

## 新增计划的流程

14. 输入一句中文 → 「生成计划」→ 显示生成的 JSON → 填关键词（可多个）→ 保存绑定。
15. 取消可以放弃这次新增。

## 校准

16. 显示「当前校准目标：<词>（n/5）」。
17. 两个按钮：「录制下一条」「录制完毕」（语义：前者结束上一段并开始下一段；后者结束并交回麦克风）。
18. 录制中要有明显状态（目标词 + 计时）。
19. 每录一段自动重算阈值，并**直接写回左侧该词的阈值输入框**。
20. 「清空该词」删除该词录音与阈值。
21. 没有选目标就点录制 → 明确提示。

## Handy（语音听写）

22. 显示 Handy 真实状态（录音中 / 空闲 / 未知）。
23. 提供手动「开始 / 停止」按钮。
24. 语音：说「听我说」开始，说「over」或「我说完了」停止。

## 非功能

25. UI 与后端只走 HTTP/JSON（将来换 exe 壳不用改）。
26. 不用任何前端构建工具（原生 HTML/JS 单文件）。
27. 视觉要干净：卡片、留白、层级清楚，不要"补丁堆出来的样子"。
