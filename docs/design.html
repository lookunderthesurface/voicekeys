二、判断流程（当前唯一逻辑）

这条顺序是明确规定的：先看有没有声音，再看 M1，M1 不自信才问 M2，问了就听 M2 的。

①
声音门槛：这段音频里有没有 >300ms 的语音？没有就什么都不做——连 M1 的判断都不采纳
免费
②
M1 判断：流式大模型持续吐字，判断由匹配器做（这句话结尾像不像某个绑定词、打多少分）。M1 本身不做判断
3–4% 单核
③
M1 很自信（≥0.95） → 走快速通道，M1 说了算，不问 M2，直接执行
省一次 M2
④
M1 不够自信 → 把这段音频交给 M2，M2 说了算：认同就执行，认为是另一个词就改判成那个词（M1 不得否决）
43 ms
⑤
M2 说"这不是词" → 丢弃，不执行（不再用 M1 兜底）
<1 ms
为什么这样分：M1 是常开的小模型（24MB，一直在解码），它的价值是便宜； 准确率的上限由 M2 决定。所以 M1 只负责"像不像"，拿不准就交给 M2，绝不反过来用 M1 去压制 M2。

实测（30 段真人录音，26 段有语音）

测法结果说明
M1 单独认对19/30 = 63%它认对的 19 段全部在 M2 认对的范围内
M2 单独认对26/30 = 87%可用音频口径：26/26 = 100%
理想裁决上界26/30 = 87%两个模型至少一个认对
当前流水线24/26 = 92%错词 0；快速通道跳过 10 次，M2 调用 14 次

结论：模型不是瓶颈，剩下的差距在"M1 只输出「平」「面」"这类情况——按规则算 M1 判"否"，丢弃。

三、静音门：三个作用，一个前提

① 区分命令与半句

门内如果文本还在变（你在继续说话），候选立刻作废。「静音门的时间里面」不会被当成「静音」。

② 隐藏 M2 的延迟

M2 的加载与推理都在门内跑完，门到期只取结果。

③ 吸收识别抖动

M1 的半句结果会反复变，门给了一个稳定窗口。

前提：门的计时从"端尾匹配命中"那一刻开始，不是从你闭嘴开始。默认：唤醒词 0ms、结束词 600ms、命令词 1000ms，每个词可在界面单独改（0–5000ms），改完立即生效。

四、素材与 Calibrator

素材 = 交给 M2 判断的那段音频（M1 自信直接执行时，则是本该交给 M2 的那段）。只记两类：

类型何时产生存什么
fastM1 ≥0.95，没问 M2音频 + M1 的词与分数
m2M1 不自信，问了 M2音频 + M1 听到的 + M2 听到的原文 + 最终判定
M1 判"否"（没有候选）→ 不记。空转写、超 6 秒没有句尾的段 → 直接丢弃，不落盘。

每条记录长这样（真实数据）：

{"id":"0021","ms":2500,"why":"m2","ourText":"站停视频","bestScore":0.85,
 "m1How":"prefix","m2Text":"暂停视频","m2Word":"暂停视频",
 "verdict":"m2-decides","fired":true}

上限默认 500 条（界面可改），存满时可选"自动删除废数据后继续"。清理规则：转写为空 / 音频无语音 / 文件缺失 / 6 秒满段。

五、执行层

项做法
执行方式常驻 PowerShell worker，不每条命令重启（省 ~400ms）
原语音量、静音、媒体、按键、Handy 开关等 11 个，参数白名单 + 自动夹紧
日志每次执行都留痕，包括"目标状态本来就满足"（例如 Handy 已在录音时再喊唤醒词）
窗口操作激活窗口不再动窗口大小（只有真的最小化才还原），不抢焦点的场景直接跳过
媒体控制的已知限制：全局媒体键（键盘上的播放/暂停键）控制不了爱奇艺——它是桌面 App，没有注册系统媒体会话。 所以媒体原语目前是"找到播放器窗口 → 激活 → 按空格 → 把焦点还回去"。代价是每次会短暂抢一次焦点，但能控制所有播放器。

八、已知问题（诚实清单）

#问题严重度现状
1M1 对短词不稳：有时只输出「平」「面」，连候选都提不出中按规则算 M1 判"否"，丢弃；靠每词阈值改善
2M2 偶尔把命令词听成同音词（如「播放视频」→「每次视频」）中策略按 M2 结果丢弃；这是 M2 精度问题
3媒体原语会短暂抢焦点（因为要激活播放器窗口）中已不让窗口变形；全局媒体键控制不了爱奇艺，暂不替换
4唤醒词静音门 0ms，M2 可能来不及给结果已缓解门到期时若 M2 没结果，会用完整音频补问一次
5指标仍是"每次命令的百分比"，不是业界口径中应改为 召回率 + 误触发/小时

九、下一步

  • 每词独立阈值：M1 一个、M2 一个，按你的发音习惯校准（不同词的可分性差很多）。素材已经在收集，够用就能算。
  • 指标改造：累计监听时长 → 同时输出「召回率」和「误触发/小时」，才能判断行不行。
  • M2 换型评估：如果短词问题持续，考虑换更强中文模型（体积会涨）。
