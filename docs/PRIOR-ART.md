# 这个设计别人做过吗？—— 先例调研（2026-11-16）

用户问得很直接：「小模型筛选、大模型决定」应该是别人玩剩下的，为什么没找到现成方案。

结论：**这个模式是成熟做法，有标准名字，但没有能直接拿来用的开源组件。**

## 一、它叫什么

| 名字 | 出处 | 和我们的对应关系 |
|---|---|---|
| **Wake Word Verification（WWV，唤醒词验证）** | Amazon，Interspeech 2020《An Audio-Based Wakeword-Independent Verification System》 | 就是我们的 M2：唤醒之后再判一次"这次是不是真的在叫设备" |
| **Two-stage / dual-stage KWS（两段式关键词识别）** | arXiv 2510.10740、2107.07634 | 轻量模型常开 → 第二段确认；我们就是这套 |
| **Cascade（级联）** | Interspeech 2005 起，2020 之后用于端侧 | 便宜的第一遍 + 精细的第二遍 |
| **False Trigger Mitigation（FTM，误触发抑制）** | Amazon 专利族 | 用廉价特征/小分类器压误触发 |

**所以不是我们发明了什么，而是独立走到了业界同一条路上。** 这本身说明方向对。

## 二、别人踩过的坑，正好能救我们

### 1. 验证模型不需要"每个词一个"（Amazon 2020）

> 他们训练的是 **wakeword-independent** 的验证器：只看"这次是不是有意的唤醒"，
> 不关心是哪个唤醒词；用对抗训练（gradient reversal）剥掉词相关信息。
> 结果：在没见过的唤醒词上也能用，效果接近专门为那个词训的模型。

对我们的含义：**不要给 21 个词各训一个验证器**。要么用一个"是否是有意命令"的通用判据
（我们现在的 M2 + policy 就是这个思路），要么用一套共享特征 + 一个轻量分类器。

### 2. 评价指标不是"准确率"，是 **FA/hour + 召回**（多篇一致）

> 两段式 KWS 的论文一律报 **"recall @ X false alarms per hour"**（例：99.13% recall @ 1 FA/h）。

我们账本现在算的是"每次命令的百分比"，这在常开场景下是**错的指标**：
- 它不区分"说了 10 条命令"和"听了 3 小时"
- 误触发的代价和时长强相关（听 3 小时误触发 5 次，和说 10 句话误触发 5 次，严重程度差几十倍）

**应该改成：**

```
召回率 = 正确触发 / 真实命令数
误报率 = 误触发次数 / 累计监听小时数
```

这两个数才是能对外说的，也才能和别人的论文对比。

### 3. 阈值要看 DET 曲线，不是拍一个数

Amazon 的 WWD 白皮书讲得很清楚：把不同算法/阈值画在 **DET 曲线**（FA vs FR）上比较，
再按场景选工作点。我们的"账本 + 阈值扫描"其实就是粗糙版 DET，可以正规化。

### 4. 多条件门控（Google，Interspeech 2021）

> 关键短语检测**只有在两个条件同时满足时**才触发：说话人验证通过 **且** 短语分数够。

这就是我们 policy 里 `agree` 规则的学术版。可以扩展成三条件：
`M1 像 ∧ M2 认同 ∧（可选）说话人匹配`。

## 三、为什么没有"现成组件"可以抄

| 项目 | 有没有 | 能不能直接用 |
|---|---|---|
| openWakeWord | 有自定义验证模型（逻辑回归，5 分钟数据） | 基础模型是英文唤醒词，中文要自己训 |
| Picovoice Porcupine | 有唤醒词 + 命令两段式 | 商业授权，自定义唤醒词要付费训练 |
| Vosk / sherpa-onnx | 只有单段识别 | 无验证阶段 |
| NeMo / ESPnet | 有 two-pass 训练配方 | 太重，要 GPU 训练 |

**所以：模式可以照抄，代码得自己写。** 我们已经把模式写出来了，接下来该抄的是他们的**指标和验证器设计**。

## 四、我们真正"自己"的部分（值得保留）

1. **静音门作为延迟隐藏机制**：把 M2 的 840ms 加载 + 43ms 推理藏进"你说完 → 命令执行"之间的
   1 秒窗口。论文里没有这个具体做法（他们通常直接用算力换延迟）。
2. **端尾匹配 + 缺字容错**：把"命令必须说完"这个语用约束变成匹配规则，
   用两个模型共识来兜住放宽带来的风险。
3. **账本驱动调参**：用真实误触发反推策略，而不是只靠离线测试集。

## 五、下一步（按先例修正）

1. **改指标**：账本增加"累计监听时长"，输出 `召回率` 和 `误触发/小时`
2. **验证器单点化**：不按词训模型，用一组共享的廉价特征 + 一个逻辑回归（Amazon 的思路）
3. **DET 化**：把阈值扫描画成 FA-FR 曲线，选一个工作点写进配置
