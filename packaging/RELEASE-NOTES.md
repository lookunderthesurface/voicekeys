## VoiceKeys v0.2.3 — Windows x64

**只下一个文件：`VoiceKeys-Setup-0.2.3.exe`**，双击安装。不需要解压 zip。

### 这一版改了什么

| 改动 | 说明 |
|---|---|
| **静音门驱动的匹配** | 以前每一帧都拿识别文本去匹配，词还没说完就会被提前匹配上（分数必然虚低）。现在只在"最后一个有声帧之后连续 3 帧静音（300ms）"时执行一次匹配；600ms 静音门从最后一个有声帧起算，第 6 帧执行或放弃。句中提到的词（后面没有静音）不再触发 |
| **两个模型都只看句尾** | M1 和 M2 都只对"这句门之前刚说的那段文本的结尾"打分，不再从整句话中间挑词。这修掉了"句中说'静音'却触发"和"长句结尾的词被句中弱词顶掉"两类问题 |
| **拼音打分更公平** | 以前一个音节错就整段掉分（挺好说/听我说 只有 0.67，卡在阈值下）。现在按音节给部分分数（韵母相同、声母相近都给分），再加长度折扣防止 3 音节碎片够到 4 音节词：挺好说/听我说 **0.67 → 0.78**，站厅视频/暂停视频 **0.75 → 0.96**，定视频/暂停视频 **0.71 → 0.53**（该拒绝的仍拒绝） |
| **修短文本门 bug** | 门之前识别文本比关键词还短时（如「天网」vs「听我说」），旧代码算不出分直接 0；现在退回整段短文本打分，能正常出候选交给 M2 |
| **删掉"同一句话只执行一次"规则** | 该规则是开发过程中临时加的，用户从未要求。现在每道静音门各自执行：一句话里说两个关键词、或同一词说两遍，只要有独立静音门就会各自触发 |
| **录音与音频窗口** | 环形缓冲 6 秒（素材 6 秒）；交给 M2 的音频固定为门前最后 4 秒，不缩短窗口（说话慢也没问题） |
| **执行日志** | 计划执行结果写进日志（含匹配到的窗口标题），媒体类动作出问题可事后定位 |

### 实测数据（70 条真实录音，1.7B 老师模型当答案）

统计口径：**分母 = 1.7B 数出的关键词出现次数**（不是录音条数），允许一条录音多次执行。

```
关键词总次数 75 次 → 命中 69 次 = 92.0%
误触发 0 次（5 条无关键词录音）
漏 6 次中：5 次是"句中提及"（本来就不该触发）
           1 次是连说两遍、间隔仅 100ms 共用一道门（说话节奏问题，非算法）
→ 排除句中提及后：69/69 = 100%
```

**已知限制**：

- 14M 流式模型偶尔把「我说完了 / 听我说 / 暂停视频」听成完全无关的词（如「天天睡觉」「天网」），这类会漏；属模型能力，后续换/升级模型再解决
- 两遍关键词之间停顿不足 300ms 时会共用一道静音门，只执行一次
- 媒体类计划是 toggle（按一次空格），同一动作执行两次会"播了又暂停"；现在有"门前只匹配一次"约束，正常说一遍不会再重复

### 装在哪里

```
程序：%LOCALAPPDATA%\Programs\VoiceKeys
数据：%LOCALAPPDATA\VoiceKeys                    模型/词表/设置/录音/日志
开始菜单：%APPDATA%\Microsoft\Windows\Start Menu\Programs\VoiceKeys\
桌面：VoiceKeys.lnk
注册表：HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\VoiceKeys
```

全部在用户目录，**不需要管理员权限、不弹 UAC**。

### 升级旧版

直接运行新 setup 覆盖安装即可；**数据目录（词表、设置、录音、模型）不会被动**。

### 校验

```
Get-FileHash .\VoiceKeys-Setup-0.2.3.exe -Algorithm SHA256
```

与 release 页面附带的 SHA256 对比一致即可。
